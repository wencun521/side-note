# 设计规范（DESIGN）

本文件定义“随手记”的视觉与动效。修改颜色、尺寸、曲线、层级前先读这里；实现值以 `src/dock.css`、`src/note-view.css` 为准，两者必须一致。

## 1. 设计立场

- **安静**：默认几乎不可见，只有一条 22px 宽的玻璃边条。
- **纸感**：便签像一张压在工作面上的纸，暖琥珀色是唯一的强调色。
- **连续**：所有出现/消失都从同一个悬浮球生长/缩回，不做淡入淡出的无源动画。
- **克制**：无渐变边框、无彩色光晕、无多余图标；层级只靠模糊、透明度和一条 1px 高光边。

## 4. 玻璃配方

### 4.1 层级

```
.note-surface     裁切容器：1px 描边、圆角、overflow hidden、scale 形变
  .note-frost     桌面截图 + blur(8px) saturate(1.32)，inset -32px
  .note-tint      白色（深色为深灰）径向 + 线性渐变，z-index 1
.note-content     内容层，z-index 2，落位后才显示
```

- 底图：`desktopCapturer` 取屏幕缩略图（显示器尺寸的 1/4），裁出面板区域，PNG dataURL 作为 `background-image`。
- `background-size: 100% 100%`：低分辨率底图被拉伸，再被 8px 模糊，形成均匀霜面。
- 玻璃必须由 `.note-surface` 裁切，保证圆角与形变过程中不露方角。
- 描边 1px `--glass-border`；贴屏幕一侧无描边（`border-*-width: 0`）。

### 4.2 禁止事项

- **不要使用 Windows Acrylic / `setBackgroundMaterial`**：材质覆盖整个矩形窗口，无法跟随圆角与形变，会先白底、再跳材质、四角呈直角。
- **不要使用 `backdrop-filter` 作为便签玻璃**：透明窗口下对桌面不可靠，且与整窗合成器行为不一致。
- **不要先显示白色/纯色底再补底图**：底图必须在打开前就绪（缓存），否则会重现“先白后玻璃”。
- **不要在形变未完成时显示内容**：文字/按钮会露出圆角裁切之外。

## 5. 形变规范

### 5.1 结构

- 舞台尺寸固定，只对 `.note-surface` 做 `scale(sx, sy)`，不做窗口逐帧改尺寸。
- 关闭态：`sx = 58 / stageW`，`sy = 58 / stageH`，`border-radius: 50%`。
- 打开态：`scale(1, 1)`，圆角按边切换为直角/24px。
- 形变原点：`transform-origin: var(--origin-x) var(--origin-y)`，由主进程按 § SPEC 4.3 计算，确保关闭态球心与 dock 球心完全重合。

### 5.2 底图反向缩放

底图必须看起来“静止”：`.note-frost` 使用

```css
transform: scale(1 / sx, 1 / sy);
transform-origin: calc(var(--origin-x) + 32px) calc(var(--origin-y) + 32px);
```

32px 是 frost 的 inset 补偿。改动 inset、原点或缩放公式时必须同步三处，否则形变中底图会滑动。

### 5.3 内容时序

| 阶段 | 内容层 |
| --- | --- |
| closed / opening | `opacity: 0; translateY(10px) scale(.996); pointer-events: none` |
| 玻璃落位（`is-ready`） | `opacity 1`（180ms）、位移归零（240ms）、可交互 |
| closing | 立即隐藏，透明度 110ms 退出 |

落位信号由渲染层 `settled()` 发给主进程，同时添加 `is-ready`。不要用固定 setTimeout 代替。

### 5.4 圆角

- 关闭态：50%（正圆）。
- 打开态：贴边侧直角，另一侧 24px；例：右侧停靠 `24px 0 0 24px`。
- 过渡：展开 500ms `--ease-bloom`，收起 330ms `--ease-close`。
- 内容层使用相同的贴边圆角，防止内容在贴边角溢出。

## 6. 动效令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--ease-bloom` | `cubic-bezier(.4,0,.2,1)` | 展开形变、吸附移动 |
| `--ease-close` | `cubic-bezier(.55,0,.8,.35)` | 收起、加速度离场 |
| `--ease-spring` | `cubic-bezier(.34,1.4,.64,1)` | 球/条弹入、轻微回弹 |
| `--ease-out` | `cubic-bezier(.22,1,.36,1)` | 内容上浮、环形弧转动 |

时长：

| 动作 | 时长 / 延迟 |
| --- | --- |
| 玻璃条 → 球 | 球透明度 180ms、缩放 340ms spring |
| 环形弧展开 | 760ms `--ease-out`，旋转 116° → 136° |
| 展开形变 | 500ms |
| 收起形变 | 330ms |
| 内容淡入 | 180ms（位移 240ms），在落位后 |
| 拖拽球吸附 | 240ms；透明度 180ms，延迟 100ms 淡出 |
| 吸附/回归条 | `bar-in` 400ms / 360ms spring |
| 保存点呼吸 | 900ms infinite |

性能规则：只动 `transform` 与 `opacity`；不要动画 `width/height/top/left`（拖拽球除外，且只在小窗口内）；不要逐帧调用 `setBounds`。

## 7. 组件规范

### 7.1 玻璃条（bar）

- 88×22 全圆角胶囊，贴边一侧为直角。
- 背景三层：底部琥珀柔光 → 左上白色高光 → 线性玻璃渐变；1px 高光边 + 双投影 + 内高光。
- 中间 16px 笔图标，琥珀色，1px 白色投影。
- `opacity: .95`；peek 时淡出并 `scale(.82)`。

### 7.2 悬浮球（ball）

- 58px 正圆，玻璃渐变 + 底部琥珀柔光。
- 1px 描边；阴影 `0 22px 44px -16px`，并带 1px 深色轮廓与内高光。
- 内含：琥珀弧线环、21px 笔图标、右下绿色状态点。
- 关闭态 `scale(.7)` 且 `opacity 0`；peek 时 `scale(1)`、`opacity 1`、可点击。
- 点击/拖拽时不得闪烁或跳位（球必须由面板球接管后再隐藏）。

### 7.3 拖拽球与参考线

- 拖拽球与悬浮球同款；出现时替换命中区，跟随指针中心。
- 参考线只在拖拽时出现（160ms 淡入），当前最近边加亮。
- 松手：拖拽球向吸附点移动 240ms 并缩小到 0.86、淡出；随后条以 spring 弹入。

### 7.4 便签

- 标题：7px 琥珀点 + 字距 0.16em 的小标题，不使用大标题。
- 工具：固定（pin）与收起（×），28px 方形圆角按钮；固定态使用琥珀色 + 柔光底。
- 正文：无边框、透明底，琥珀色光标与选区；占位符“随手写点什么…”。
- 页脚：保存状态（5px 点 + 文案）、操作提示、低对比“退出”。
- 不允许出现滚动条以外的原生控件样式；无边框按钮统一使用 9px/6px 圆角。

### 7.5 状态类

| 类名 | 作用 |
| --- | --- |
| `is-peek` | 条淡出、球弹出 |
| `is-hidden` | dock 内容隐藏（面板打开） |
| `is-grabbing` / `is-dragging` | 隐藏命中区、显示拖拽球与参考线 |
| `is-releasing` | 隐藏参考线 |
| `is-snapped` / `is-returning` | 条弹入动画 |
| `is-open` | 便签圆角与内容过渡切换到展开态 |
| `is-ready` | 内容可见、可交互 |
| `is-closing` | 内容快速退出 |

## 8. 深色模式与动效偏好

- 通过 `prefers-color-scheme: dark` 切换令牌；玻璃改为深灰渐变，描边降为 16% 白。
- 底图兜底色 `#1c2029`；选中态与按钮底色使用白色透明度而不是固定灰色。
- `prefers-reduced-motion: reduce`：所有过渡与形变降到 1ms，关闭弹入动画与保存点呼吸。

## 9. 无障碍

- 命中区是原生 `button`，保留焦点环样式与 `aria-label`；由于 dock 窗口 `focusable: false`，键盘通常无法聚焦到它，交互以鼠标为主。
- 所有图标按钮有 `aria-label` 与 `title`；装饰元素 `aria-hidden`。
- 正文支持键盘输入、选区与滚动；Esc 收起。
- 颜色对比以正文为主，页脚等次要信息允许低对比但不承担关键操作。

## 10. 改动原则

1. 新增颜色/阴影/圆角先加令牌，不要在组件里写魔法值。
2. 视觉尺寸变化必须同步 `SPEC.md` 的几何表与 `main.cjs` 的常量。
3. 任何形变相关改动都要检查：球心是否重合、底图是否漂移、内容是否提前出现、直角是否露出。
4. 任何“更炫”的效果（发光、彩色渐变、粒子、弹簧过冲）默认不加；这个产品的核心是安静和连续。
